> **⚠ Breaking for existing sessions.** The plug-in's hidden identifiers have changed on purpose (approved by the project owner).

> the host will report it missing. Re-insert **SynSyn 1000** and load your sound from a preset (see below).
> The old and new plug-ins can be installed side by side.

### Windows build — not produced (blocked)
- MinGW-w64 (GCC 14.2, posix threads) and Wine 10.0 were installed. **JUCE 8 refuses to compile with MinGW**: `juce_TargetPlatform.h` contains `#error "MinGW is not supported. Please use an alternative compiler."`, and JUCE's BREAKING_CHANGES.md (8.0.1) states MinGW support was removed and that cross-compiling for Windows from Linux "is not supported, and there is no workaround". A probe build with that `#error` removed still fails: missing Direct2D 1.3 interfaces (`ID2D1DeviceContext3`, `ID2D1SpriteBatch`) and newer UI Automation interfaces in the MinGW-w64 12 headers. See NOTES.md for options.
- `CMakeLists.txt` is Windows-ready for a supported compiler (MSVC or clang-cl): on Windows it builds VST3 + Standalone only and skips the VST3 manifest step when cross-compiling.

## 0.6.0 — Milestone 6: USB MIDI in the Standalone, MIDI LED (2026-11-10)

### Fixed
- **USB MIDI keyboards didn't play the Standalone** (reported with an Arturia MiniLab 3 on Ubuntu 26.04, PipeWire/ALSA). The OS saw the device and the build had ALSA MIDI support (`JUCE_ALSA=1`, libasound linked, `IS_SYNTH`/`NEEDS_MIDI_INPUT` on, device MIDI merged in `processBlock`), but JUCE's desktop Standalone wrapper **opens no MIDI input devices by default**. `autoOpenMidiDevices` is only on for Android/iOS, so on Linux every input stayed unticked in Options › Audio/MIDI Settings, and no MIDI reached the synth.
  - New `Source/standalone/StandaloneMidi.*`, compiled into the plugin target only and created from `createPluginFilter()` when `wrapperType == wrapperType_Standalone`:
    - At startup it enables every available MIDI input. New devices are enabled when they're hot-plugged, detected through `juce::MidiDeviceListConnection` with a 1 s poll as a fallback. Devices that disappear are closed so that a re-plugged one is opened again.
    - **The settings dialog is respected.** A device you untick there is remembered by name in the Standalone's settings file (`~/.config/VST Forge Synth.settings`, key `vstforgeMidiDisabledInputs`) and isn't auto-enabled again until you tick it.
  - VST3 and LV2 behaviour is unchanged. They already accept host MIDI (VST3 event input bus; LV2 `atom:AtomPort` input with `midi:MidiEvent`); the host routes the keyboard.

### Added
- **MIDI LED** in the title bar (a "MIDI" label and a round red lamp, left of the version):
  - **Dark:** no MIDI input confirmed.
  - **Steady red:** MIDI input connected. In the **Standalone** this means at least one MIDI input device is enabled and open. In a **plugin** (VST3/LV2) it means the host has delivered at least one MIDI message to this instance. That state is latched, because hosts don't tell plug-ins about device connections.
  - **Brighter flash** (90 ms) on every incoming channel message (notes, CC, pitch bend, aftertouch, program change). Clock, sysex and active sensing count as "connected" but don't flash.
  - Only external MIDI counts. It's measured before the on-screen keyboard and wheels are merged in.
  - The audio thread only does relaxed atomic stores and increments, with no locks and no allocation. A 30 Hz UI timer reads them and repaints only on a state change.
- **Tests:** a fresh instance is off; the on-screen keyboard isn't counted; clock gives connected with no flash; 8 host notes give 16 activity ticks; the Standalone open-device count decides; the LED goes off → on → flash → on; `renders/m6_editor.png` shows the lit LED.

### Compatibility
- Audio is untouched. All 25 WAV renders are byte-identical to the M5 build, and the M1–M4 reference sessions still match with max |diff| = 0. Parameters, state format (`stateVersion` 3) and presets are unchanged; the version string is now 0.6.0.

## 0.5.0 — Milestone 5: presets (2026-11-09) — first-version feature set complete

### Added
- **Preset system** (`Source/presets/PresetManager.*`):
  - Presets are human-readable XML files (`.vfpreset`): the full APVTS parameter state plus name, category, author, plug-in version and a format number.
  - **User presets** live in `~/.local/share/VSTForgeSynth/Presets/<Category>/<Name>.vfpreset`. `$XDG_DATA_HOME` is honoured, and `VSTFORGE_PRESET_DIR` overrides the location.
  - **Factory bank:** 24 presets embedded in the binary via BinaryData and parsed into memory. They are read-only; Save on a factory preset opens Save As to make a user copy.
  - **Categories:** Bass, Lead, Pad, Pluck, Keys, FX and User. The "User" filter shows all user presets.
  - **Init** (all defaults) is entry 00.
  - Loading is robust: missing parameters fall back to their defaults, unknown IDs are ignored, non-finite values are replaced and out-of-range values are clamped. Corrupt, empty, truncated, wrong-root and newer-format files are skipped on scan, and a failed load leaves the state untouched.
  - Saves are atomic (written to a temp file, then renamed). Save As asks before overwriting.
  - **Modified detection** compares the current parameters against those of the loaded or saved preset.
- **Host integration:**
  - Factory presets are exposed as **JUCE programs**: Init plus 24 (`getNumPrograms`, `setCurrentProgram`, `getProgramName`, `getCurrentProgram`). Program changes never touch the disk.
  - The plug-in state stores the current preset (name, category, kind, file, modified flag) and restores it. `stateVersion` is now 3.
- **Glitch-free loading:**
  - A preset load is signalled to the audio thread. If anything is sounding, the output fades out over 10 ms while the old voices keep the old preset's parameters (frozen voice, effects and gain snapshots).
  - Then every voice is stopped and the effect tails are cleared.
  - Note on/off events that arrive during the fade are deferred and replayed in order, so nothing is lost and no note gets stuck.
  - When nothing is sounding, the switch is instant.
  - No file I/O ever happens on the audio thread.
- **UI** (`Source/gui/PresetBrowser.*`, SynprezFM "Memory" style):
  - **Memory section** in the top strip:
    - Bank filter LCD and prev/next arrows (they wrap within the bank).
    - Patch LCD with the orange preset number, and a category/kind LCD that also shows short status messages.
    - An orange **EDITED** lamp.
    - Buttons: List, Init, Save, Save As, Rename, Delete. Rename and Delete only work on user presets.
  - **Preset Browser** overlay with category tabs and a grid of preset LCD cells (click to load, double-click to load and close), plus the user folder path, Rescan and Open Folder.
  - **Dialogs** are in-editor overlays: Save As (name, category, author), Rename, and confirmations. Deleting asks for confirmation and names the file that will be removed.
  - The design size is now **1200×760** (the Volume and Memory section sits beside the oscillators). Resizing still works.
- **Factory presets:** 24, four per category, using all the synth's features. Levels are tuned so each preset's category phrase peaks at about −4.5 dBFS with no limiting. The sources are `presets/make_factory_presets.py`, `presets/levels.json`, `presets/tune_levels.py` and `presets/factory/**/*.vfpreset`.
- **Tests:**
  - Factory bank and program switching through the host API.
  - Save → load round trip: state identical, re-save byte-identical.
  - Session restore of the preset name and modified flag.
  - Save As, overwrite, rename, delete and read-only checks in a temp dir.
  - Corrupt or missing files, and values that need clamping.
  - Switch fade (click-free, then silence, deferred note).
  - Every factory preset rendered.
  - UI flows (Save As dialog, confirmed delete, browser filter).
  - Compatibility with the v0.4.0 references (6 scenarios, including the new `m4_session`).
- `renders/m5_preset_tour.wav` (38 s, 12 presets), `m5_editor.png`, `m5_browser.png`, `m5_saveas.png`.

### Compatibility
- No audio-path change for existing sessions: M1–M4 sessions render **sample-identical** to v0.4.0, with max |diff| = 0 across 6 reference scenarios.
- Sessions from before M5 show the preset as "Init". The EDITED lamp tells whether such a session differs from the defaults.

### Fixed
- VST3 state restore now restores bool parameters exactly. Previously a raw bool value such as 0.75 survived `setStateInformation`, which pluginval's state-restoration test caught at strictness 10.

## 0.4.0 — Milestone 4: effects (2026-11-09)

### Added
- **Effects chain:** chorus → delay → reverb. It runs after the voice sum and master gain, and before the safety limiter. The output is always stereo; a mono output bus gets the stereo effects folded down to mono.
- **Chorus:** on, rate (0.05–5 Hz), depth, mix. It uses 4 cubic-interpolated taps with quadrature LFO phases, giving 2 taps per side, a 9 ms base delay and up to 8 ms of sweep.
- **Delay:**
  - On, time (1–2000 ms), or **tempo sync** with the LFO divisions (4/1 to 1/32, including dotted and triplet; the default is 1/8 D). It uses the host BPM, or 120 when there isn't one.
  - Feedback is 0–95 %, with a soft saturator in the loop (transparent below 0 dBFS) so extreme settings stay bounded.
  - **Ping-pong**, a one-pole **high-cut** in the feedback path (500 Hz–20 kHz), and mix.
  - The maximum time is 4 s. Time changes are smoothed over about 0.2 s, which sounds like a tape-style pitch glide rather than clicks.
- **Reverb:** on, size, damping, width, **pre-delay** (0–200 ms) and mix. It's built on `juce::Reverb`, with an allocation-free pre-delay line.
- **For every effect:**
  - A 30 ms bypass ramp.
  - Zero CPU when fully off; buffers are cleared when the effect is switched back on.
  - Tails ring on after note-off.
  - Latency is 0.
  - `reset()` clears all effect state.
  - No allocations on the audio thread, since buffers are sized in `prepareToPlay`.
  - `getTailLengthSeconds()` reports the delay and reverb tails.
- **UI:** a fourth **Effects** strip with Chorus, Delay and Reverb panels, each with an LCD for every parameter and a live display (the chorus taps, the echo train with ping-pong sides, and the reverb decay with pre-delay). The design size is now **1100×760**. Resizing still works, and the window opens at the saved size or shrinks to fit the screen.
- **Tests:**
  - Each effect alone, plus all three together.
  - Delay at 95 % feedback with ping-pong and a time sweep, checked for no runaway by estimating the pre-limiter level.
  - Reverb tail: it continues after note-off and drops below −90 dBFS, with no denormals.
  - reset(), the bypass-ramp click check, and the mono bus.
  - 44.1/48/96 kHz renders plus a sample-accurate delay-time check.
  - Stereo width for chorus, ping-pong and reverb.
  - **v0.3.0 reference compatibility** with max |diff| = 0.
- `renders/m4_demo.wav` (12 s) and `renders/m4_editor.png`.

### Compatibility
- All the effect parameters (version 4) default to off. Sessions from M1, M2 and M3 render **sample-identical** to v0.3.0, which the tests verify against 5 reference scenarios, including the new `m3_session`.

## 0.3.0 — Milestone 3: LFOs (2026-11-09)

### Added
- **Two LFOs**, each with:
  - Waveforms: sine, triangle, saw up, saw down, square, sample & hold.
  - Rate from 0.01 to 40 Hz on a log scale, or **tempo sync** to host BPM. Divisions run from 4/1 to 1/32, including dotted and triplet. The tempo falls back to 120 BPM when there's no host tempo, as in the standalone.
  - Depth, a **Retrig** mode (per voice, restarts at note-on) and a **Free** mode (global, locked to the host timeline when synced and playing).
  - Delay (a linear fade-in after note-on) and a phase offset.
  - **One assignable destination with a bipolar amount:** none, cutoff (±4 oct), resonance (±100 %), pitch for all oscillators (±12 st), pitch of oscillator 1, 2 or 3, level of oscillator 1, 2 or 3, or amp (tremolo).
- **Mod wheel (CC1) depth scaler for LFO 1.** It's optional (the `ModWhl` toggle) and is meant for vibrato. It responds to host MIDI and the on-screen wheel.
- **Zipper-free modulation:**
  - LFOs are evaluated per sample and pass through a 2 ms one-pole smoother, which also smooths S&H and square steps and automation jumps.
  - Pitch, cutoff and resonance update every 8 samples; levels and amp update per sample.
  - Level and amp destinations only ever reduce gain, staying in the range [1−|amt|, 1], so tremolo can't overload.
- **UI:** a third strip with LFO 1 and LFO 2 panels, using LCD readouts for Wave, Rate, Sync, Div, Dest, Amt, Depth, Mode, Delay and Phase (plus ModWhl on LFO 1), and an animated waveform display with a playhead.
  - Strip and keyboard heights were trimmed: the design size is now 960×656, and resizing still works.
  - On first open, the window shrinks to fit small screens.
- Tests:
  - Sample-exact v0.2.0 compatibility renders (`tests/reference/`).
  - Vibrato, square and saw wobble, tremolo, delay/fade-in, S&H, mod wheel, and max-depth stress renders.
  - Modulation measurements: pitch tracking, brightness autocorrelation and the RMS envelope.

### Compatibility
- All the new parameters default to destination None with amount 0. Sessions from M1 and M2 render **sample-identical** to v0.2.0, and the tests verify it with max |diff| = 0.

## 0.2.0 — Milestone 2: oscillators, filter, safety (2026-11-09)

### Added
- **Oscillators 2 and 3.** Each has the same 5 waveforms, plus on/off, level, coarse (±24 st) and fine (±100 ct). Oscillator 1 gets the same controls. Oscillators 2 and 3 start each note at a decorrelated phase.
- **Per-voice resonant filter.** A TPT state-variable filter (Simper/Zavalishin) with low-pass, high-pass and band-pass. Cutoff runs 20 Hz–20 kHz on a log scale, smoothed in octaves. Resonance maps Q from 0.707 to 20 and is always stable. Key tracking runs 0–100 %, and envelope amount is bipolar ±7 octaves.
- **Filter ADSR envelope.**
- **UI:**
  - The Oscillator strip now holds Volume and Oscillators 1, 2 and 3, each with an on/off LCD and a waveform display.
  - A second strip holds Amp Envelope, Filter (with a live response-curve display) and Filter Envelope (with an ADSR display).
  - On/off parameters toggle with a click.
- New render tests: a 3-oscillator detuned chord, a filter sweep, a high-resonance stress render, a +6 dB 16-voice limiter check, a waveform-switch click check, M1 session compatibility, and editor size persistence.
- `renders/m2_demo.wav` and `renders/m2_editor.png`.

### Fixed (M1 known issues)
- An output safety limiter keeps output below 0 dBFS. It has an instant attack, an 80 ms release and a −1 dBFS ceiling, and it also scrubs NaN/Inf. +6 dB with 16 voices no longer exceeds 0 dBFS.
- The editor size is saved in the plugin state and restored when the editor reopens.
- Waveform switches no longer click. The phase stays continuous, with a 5 ms crossfade between the old and new waveform.

### Compatibility
- Parameter IDs from M1 are unchanged. When an M1 session loads, any parameter missing from it is set to its default: oscillator 1 on at 100 %, oscillators 2 and 3 off, and the filter open (low-pass at 20 kHz, flat Butterworth Q). M1 sessions sound the same.

## 0.1.0 — Milestone 1: playable foundation (2026-11-09)

### Added
- JUCE 8.0.15 CMake project producing **LV2**, **VST3** and **Standalone** builds of "VST Forge Synth".
- 16-voice polyphonic synth (`juce::Synthesiser`, note stealing on).
- Oscillator 1 with Sine, Saw, Square, Triangle and Noise. Saw and square use PolyBLEP, triangle uses PolyBLAMP, and noise is xorshift.
- ADSR amplitude envelope, velocity-sensitive with a smoothed per-voice level.
- Master gain from −60 to +6 dB, smoothed multiplicatively.
- Host-automatable parameters through `AudioProcessorValueTreeState` (IDs are stable and versioned), with state save and restore.
- Pitch bend of ±2 semitones from host MIDI or the on-screen wheel. The mod wheel sends CC1, which isn't routed to anything yet.
- Editor styled after the SynprezFM layout: black background, titled strip sections with teal outlines, pale-green LCD readouts, orange accents, an ADSR shape display, a waveform display, and a vertical volume fader. The keyboard is full width, with octave arrows, a range overview and a Pitch/Mod column. The window can be resized, and the layout scales uniformly.
- `VSTForgeRenderTest` offline render and check tool, which writes WAVs and an editor snapshot.
